# Task 02 Answer

### **回答正文**

- 1. 
    【题目】
    为什么 `./tools/recruit-info` 能运行，而直接输入 `recruit-info` 可能找不到？

    【回答】 
    `./tools/recruit-info` 实际上是一种表示相对路径的写法。
    `.` 表示当前所在的目录，由于我当前所在的目录是 `~/projects/Jotang-recruit/linux-shell-recruit-absolute-value` ，且 `recruit-info` ==的确==处于这个目录的下级，同时已经用 `chmod +x tools/recruit-info` 修改过我对该文件的权限，变为==可执行==。所以能运行这个文件。
    而直接输入 `recruit-info` 不包含 /，Shell 将其视为命令名，只会去 PATH 环境变量列出的目录中查找，由于此时还未设置PATH，tools 目录不在 PATH 中，所以找不到。

    另：【学习心路历程补充】
    
    我直觉上认为 `./tools/recruit-info` 是一个相对路径，如果要查看内容应当需要某个函数（“动作”）牵头，类似于 `cd` `cat` 什么的。
    
    但实际上经查询： Shell 会检查是否包含  `/` ？

    （删除线略去看不懂同时直觉上无需特别记忆的内容）

    1. 如果包含 `/` （如本例）：Shell 直接进入 “路径执行模式”。它会跳过PATH 查找，直接把这个字符串当作文件路径，~~调用 fork() 创建子进程，然后调用 execve() 系统调用，~~尝试加载并执行这个路径指向的文件。
    如果此时有执行权限（ `-x` ）则可以直接加载到内存中运行。

    2. 如果不包含 `/` （如 `ls` ）：Shell 才进入 “命令查找模式”。它会依次检查：别名 → 关键字 → 函数 → 内置命令 → 最后去 PATH 环境变量列出的目录里搜寻。

- 2.  
    【题目】
    Shell 输入 `ls` 时如何找到程序？

    【回答】
    `ls` 是 Shell 通过 PATH 遍历，在`/usr/bin/ls`中找到的可执行程序。

    【学习笔记补充】
    Shell 查找 ls 的过程，就是严格按照 “别名（设置的alias） → 关键字（语法保留字`if`,`for`等） → 内置（自带命令`cd``echo`） → 哈希缓存（之前对话中是否运行过`ls`） → PATH 遍历（读取环境变量，按顺序进入目录，查找具有执行权限的文件）” 的优先级顺序，找到第一个匹配项并立即执行。
    最终在 `/usr/bin` 里找到 `/usr/bin/ls`。
